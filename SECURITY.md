# Security policy

## Supported versions

The latest release receives security fixes.

## Reporting

Do not open a public issue for a vulnerability. Use GitHub's private vulnerability reporting for the repository. Include reproduction steps, affected versions, and impact.

## Safe operation

Monitor only domains you control or are explicitly authorized to assess. SpoofScope performs bounded public DNS, TLS and HTTP observations; it does not prove malicious intent.

For production deployments:

- Set long random values for `POSTGRES_PASSWORD` and `SPOOFSCOPE_API_KEY`.
- Terminate TLS at a trusted reverse proxy and restrict network access where possible.
- Keep PostgreSQL and Redis unpublished; the supplied Compose file publishes Nginx only on the host loopback interface by default.
- Apply outbound firewall rules in high-assurance environments. Application checks reject non-public destinations, but DNS rebinding protections are strongest at the network layer.
- Treat screenshots as potentially sensitive data and protect the screenshot volume and backups.
- Choose a retention period appropriate to your privacy and evidence requirements.
- Review container and dependency updates generated by Dependabot.

The built-in API key provides single-tenant access control. It is not a replacement for multi-user identity, RBAC, SSO, or audit-grade user attribution.

## Security boundaries

SpoofScope never submits discovered forms, stores credentials, performs vulnerability exploitation, bypasses authentication, or scans arbitrary ports. A score represents review priority only. Analysts must validate evidence independently before escalation or takedown activity.
